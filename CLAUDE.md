# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Hype is a terminal text art generator written in Rust (edition 2024). It renders images as colored text using half-block, braille, or ASCII characters with support for truecolor, 256-color, and grayscale output.

## Build & Run

```bash
cargo fmt                # format code (run after changes)
cargo clippy             # lint (run after changes, fix any warnings; CI uses -D warnings per feature)
cargo build              # debug build
cargo build --release    # release build
cargo test                # run tests
cargo deny check         # dependency policy: advisories, licenses, sources, bans (deny.toml)
cargo run -- <image> [options]  # run directly
```

Glyph data: `src/recursive.rs` is generated by `build/glyphs.py` (offline; not part of the cargo build) from a hash-pinned Recursive font release: outlines (upright and italic, five weights) as compact relative SVG path data in half font units — `t` for TrueType's implied-midpoint curves, verified to round-trip on every run — measured 2×4 subpixel coverage tables, and each fit's SVG transform (precomputed as text so no float formatting is linked in). The generator writes rustfmt-stable output; check with a regenerate + `cargo fmt` + diff after changing it. Setup and usage are in the script's docstring (system `python3` venv, hash-pinned fontTools); `--proof FILE.svg` writes a sheet of the outlines for checking by eye. Its outline data is under the SIL OFL (`LICENSE-Recursive.txt`), not MIT.

Releasing: `build/tag.sh X.Y.Z` (on an up-to-date master) bumps `Cargo.toml`, commits, tags and pushes. The tag runs `.github/workflows/release.yml`, which builds static binaries (macOS arm64/x86_64, Linux musl arm64/x86_64) and attaches them with `checksums.txt` to a GitHub release. Then run `release.sh X.Y.Z` in the `homebrew-hype` tap to point the formula at them.

## Architecture

Source files in `src/`:

- **main.rs** — CLI argument parsing (hand-rolled, no clap; a long option's value follows a space or `=`, a short option's a space, and an optional value — `--text[=FILE]`, `--tint[=N]` — only `=`, so no option guesses whether the next word is its value; documented in the help's output contract), output sizing (`target_size`), and dispatch to render functions. With `--layer`, further images are decoded straight to their fitted size (`fit_size`), centered, and composited over the first image's canvas before rendering. Rendering mode (`Block`/`Braille`/`Ascii`) and color mode (`True`/`Ansi256`/`Gray`) are determined here. Output is built into one byte buffer and written once.
- **decode.rs** — Format sniffing by magic bytes and decoders that stream RGBA rows into the resampler. PNG (`png` crate) and JPEG (`zune-jpeg`) are default features; GIF (`gif`), WebP (`image-webp`) and BMP (hand-rolled, incl. RLE4/8) are opt-in cargo features.
- **resize.rs** — Streaming resampler: exact integer box pre-reduction (keeping a ≥2× "reducing gap") followed by separable Lanczos3, on premultiplied alpha. Vertical filtering gathers from a ring of the last few horizontally filtered rows, so each output row is quantized as soon as it is complete and only the 8-bit output is held. The full-size source image is never held in memory (except JPEG, interlaced PNG, GIF and WebP, whose decoders produce whole frames).
- **render.rs** — All rendering logic. Each mode has its own public function (`render_block`, `render_braille`, `render_ascii`) writing into a `Vec<u8>`. `Sgr` tracks terminal color state and emits only changes, combining fg/bg into one escape. Also alpha compositing (`apply_bg`, and `overlay` for layers), dithering (Floyd-Steinberg, ordered Bayer 4×4) for 256-color block mode, and the measured ASCII glyph coverage table (`GLYPHS`).
- **color.rs** — Color math utilities: integer BT.601 luminance (`lum1000`), ANSI 256-color nearest-match (6×6×6 cube + grayscale ramp), perceptually-weighted color distance, and alpha blending.
- **svg.rs** (cargo feature `svg`) — `--svg` output for ascii, `--text` and braille. Runs the same per-cell decisions as render.rs (`flatten`, `cell`, `ascii_glyph` with the Recursive ramp, `lit_mask`, `compensate`). Glyphs are labeled (char, weight index into `recursive::WEIGHTS`: 400, 600, 800, 875, 1000, chosen in `build/glyphs.py` for even steps of ink, as a 400/1000 pair looked jarring) and all weights share one ramp, so the weight is chosen with the glyph; `--text` instead takes the weight whose average lowercase ink (`ref_inks`) is closest to the ascii glyph's, as the ascii glyph may be e.g. a faint heavy '.'. Weight is chosen for the image, never for text legibility. It then writes each used shape once in `<defs>` (glyph paths with `recursive::TRANSFORM`; braille masks as circles) and a `<use>` per non-blank cell, cells 1×2 units. `--svg` defaults to ascii mode and truecolor; `-c gray` is one ink color. `--tint[=N]` (svg only, default 50) puts a crisp-edged 1×2 path behind each drawn cell (a plain element, not a `<use>`: Chrome instantiates each `<use>`, and per-cell tint uses took a mural 3 s → 40 s to open) (and `--text` word spaces): the tone the glyph can't carry (cell total minus coverage × ink, spread over the uncovered area), capped per channel at N% of the ink in `flatten`ed space so glyphs stay legible; at 75 pale glyphs wash out. Glyphs are enlarged to fill the cell (the `fill` geometry in `build/glyphs.py`): the font's own proportions (`natural`, kept in the generator's report only) leave gutters that narrow the tonal range, and SVG exists to represent the image, not to keep type's proportions.
- **recursive.rs** — Generated glyph data (see Build & Run); OFL-licensed.
- **term.rs** — Terminal width via a direct `ioctl(TIOCGWINSZ)` FFI call (stdout, then stderr, then stdin), and `isatty`. Unix only.

Key design points:
- Goal: minimal resource cost per invocation (startup, RSS, binary size) — hype is meant to be shelled out to on demand by other terminal apps. Prefer brutally simple code; add complexity only for a measured win. Release profile uses fat LTO, 1 codegen unit, `panic = "abort"`, strip, opt-level 3 (`"s"` measured ~2× slower for ~80 KB savings).
- Every mode samples each character cell as 2×4 subpixels (`cell()`), so `target_size` is mode-independent.
- Block mode fits each cell: of the seven two-region half-block/quadrant shapes (`SHAPES`), pick the one whose side means, as the terminal will display them (`Sgr::shown`, so 256-color is fit in-palette), give the least perceptual error. Uniform cells become a background-colored space; the glyph or its complement is chosen to minimize color changes. Partly transparent cells draw the shape nearest the opaque subpixels over the default background. Without `--bg`, translucent pixels are first faded toward black (the assumed dark terminal), which keeps silhouette edges antialiased.
- Braille and ASCII have one color per cell over the (assumed dark) terminal background, and see translucent pixels composited over black. `--light` (`Backdrop.light`) assumes a light background instead: `flatten` composites over white and inverts the image, the unchanged dark-background logic runs on that, and `Sgr` inverts colors back on output. This is exact, not an approximation, because `color_dist` depends only on channel differences and `lum1000` is linear; keep both true. Block mode only fades translucent edges toward white. `lit_mask` decides which subpixels to draw: above the threshold, and better represented by the lit pixels' mean color than by black. Braille lights exactly those dots; ASCII treats a cell the mask splits as an edge and picks the shape-matched glyph, else uses the density ramp on mean luminance.
- `--text[=FILE]` (implies ascii; stdin without a file) draws the file's text instead (`prepare_text`: whitespace collapsed, typographic punctuation mapped, other non-ASCII dropped; Gutenberg `_italic_` markup dropped with the characters flagged by `ITALIC`, bit 7, which the terminal masks off and svg.rs draws with Recursive's italic outlines and coverage — an underscore opens at a word start, closes at a word end, is literal otherwise, and a paragraph break ends italics): each cell ASCII mode wouldn't leave blank takes the next character, repeating. Color is the ink-weighted cell color scaled by `REF_INK`/coverage (`compensate`) so thin and heavy glyphs look equally bright; glyphs missing from `GLYPHS` get the plain cell mean.
- Options that would have no effect in the chosen mode (`-t` outside braille, `-d` outside block, `--tint` without `--svg`, ...) are errors, not silently ignored, so a script or agent learns of the mistake. Decide them from the arguments only, never the environment: `-d` without `-c` selects 256-color rather than failing on a truecolor terminal.
- Dithering only applies to 256-color block mode; it averages cells down to plain half-block pixels, quantizes to the 6-level cube, and renders with `▀`/`▄`.
- Each output line ends with no color state set, so lines stand alone when consumers slice output. `--help` documents this output contract for agents; keep it accurate. Help styling and the logo appear only when stdout is a TTY and `NO_COLOR` is unset. The logo is `banana.png`, embedded and rendered by hype itself as large as fits beside the help (`logo()`).
- Terminal color support is auto-detected from `COLORTERM` env var, falling back to 256-color.
